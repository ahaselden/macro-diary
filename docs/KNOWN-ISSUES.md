# Known issues

Collected from extraction agents and the regression reviewer during the refactor. Per [D8](DECISIONS.md#d8-bugs-found-during-a-refactor-are-logged-not-fixed) these were **not** fixed while behaviour had to stay identical. Each says whether it has since been fixed.

| # | Issue | Severity | Status |
|---|-------|----------|--------|
| 1 | Imported backup strings reached HTML unescaped (`data-edit="${e.id}"`, `value="${amount}"`, goals) and `goals` was not validated, so a crafted backup file could inject markup. | Medium (security) | Fixed in refactor phase 4 (see commit log) |
| 2 | Service worker precache list omitted `css/` and `js/`; offline before first fetch would break. | Medium | Fixed in phase 5 |
| 3 | Share summary text says "dayly summary" for the day range (built from `x.kind + 'ly'`). | Low (cosmetic) | Open |
| 4 | `volOf('cups of tea')` is read as one cup (the unit only needs a word boundary after it). Harmless for real measure text. | Low | Open |
| 5 | `frac(null)` throws; only ever called with regex-matched text so unreachable today. | Low | Open |
| 6 | `validEntry` accepts `grams` given as a numeric string; the measures filter does not check `g` is a number. | Low | Open |
| 7 | `newEntries` doesn't dedupe repeated ids *inside one backup file*. | Low | Open (superseded by the Stage 1 merge rewrite) |
| 8 | Foods with empty name/brand/source share the `foodKey` `"||"` (and so share saved measures). | Low | Open |
| 9 | Export: a range containing only empty days exports summary+JSON but no entries CSV (each file has its own "nothing to export" test). | Low | Open (arguably correct) |
| 10 | Barcode: if `BarcodeDetector` were missing after the camera was granted the stream was left running. The scan button is only shown when it exists, and the new `barcode.js` is DOM-free. | Low | Mitigated |
| 11 | The embedded preview browser doesn't register service workers, so offline behaviour can only be verified in a real browser. | Info | Open — owner to check on phone |
| 12 | **The Supabase SQL (`docs/SYNC-SETUP.md`) has never run on a real Postgres**; the adapter was verified only against a mock written from the documented API. Riskiest parts: `#variable_conflict use_column`, `insert … on conflict do nothing returning`, the `SECURITY DEFINER` function. Expect to possibly fix a syntax error on the first run. Since the repo is connected to Supabase, the first real run is the migration on merge to `main` (see SYNC-SETUP.md section 2). | **High** (blocks sync going live) | Open — the migration applied (owner confirmed the `records` table and `push_record` exist in the dashboard, 2026-11-10) but no real sync has called `push_record` yet. Close once the checklist in SYNC-SETUP.md section 6b passes |
| 13 | Device clocks are trusted for "which edit is newer" (a badly wrong clock can win or lose edits). | Medium | Accepted (D9); a hybrid logical clock would fix it |
| 14 | Two devices editing *different meals of the same planned day* while offline keep only the newer device's day (day is the merge unit, D13). | Low | Accepted |
| 15 | The sync cursor can theoretically skip a row when two server transactions commit out of order (noted by the adapter's author). Negligible for one user; an occasional full re-pull from a null cursor would remove it. | Low | Open |
| 16 | Supabase push is not atomic across records; an error mid-push leaves earlier records written. The engine treats any thrown error as "unknown" and re-pulls, so it self-heals. | Low | Mitigated |
| 17 | Recipe import from a URL is not built (needs a server-side proxy because of CORS). | Feature gap | Deferred (PLANNER.md) |
| 18 | Parser keeps "large"/"small" in names ("2 large eggs" → name `large eggs`) as the C# did; only the shopping list ignores size words for grouping. Recipe search for "eggs" still matches. | Low | Open |
| 19 | Shopping ticks are scoped to the shopping range (fixed after review), but old weeks' ticks are never pruned and a renamed ingredient orphans its tick. | Low | Accepted (D16) |
| 20 | `shareText` summary says "dayly" for the day range — see #3. Planner share text is unaffected. | Low | Open |
| 21 | Not verified on a real phone or real iOS/Android browsers: install/icon, camera barcode scan, offline service worker (the preview pane can't register one). | Info | Owner to check |
| 22 | The USDA demo key is rate-limited; household measures and recipe food linking need the owner's own key in Settings. | Info | By design |
| 23 | Parser edge cases (found by review, not fixed): `"1 1/2 cups"` (no ingredient name) gives an empty name; `"1e5 g x"`, `"1.5.5 cups x"` and `"-5 g salt"` mis-parse the number. Real recipe lines rarely look like this; the editor lets you correct the text. | Low | Open |
| 24 | Editing an ingredient's raw text recomputes its grams, discarding grams the user typed by hand for that linked food. | Low | Open |
| 25 | Foods picked into a recipe/plan share `per100`/`portions` object references with `state.custom`/`state.recent` until the next reload (no mutation happens today). | Low | Open |
| 26 | Restoring a backup or wiping data doesn't emit `recipes:changed`/`plan:changed`; harmless because those screens re-render when shown. | Low | Open |
| 27 | `plan-view` / `shop-view` re-render the whole tab on change. Mitigated (typing is protected and quantity edits refresh after a short delay, so taps aren't swallowed), but a finer-grained render would be nicer. | Low | Mitigated |
| 28 | Review findings that WERE fixed: an unescaped unit crashed `resolveGrams`/nutrition for a crafted or synced recipe (units are now whitelisted + escaped); absurd quantities (1e300) are rejected on load; `copyDay` onto the same day wiped it; `aisleOf` matched word prefixes (eggplant → dairy); `family()` read `Object.prototype` for units like `toString`; ticks leaked across weeks; Esc/backdrop closed the recipe editor silently (now asks to discard changes). | — | Fixed (see commit) |
| 29 | The camera/scanning path (native and ZXing fallback) has only been tested up to the camera: decoding is tested on real barcode pixels in Node (and was checked by hand on a browser canvas, which is not reproducible from the repo), but nobody has scanned a physical package yet. Low light, glare and curved labels are the likely weak spots; typing the digits always works. | Medium | Unverified on a device |
| 30 | `js/vendor/zxing.min.js` is a copy that will not receive security updates automatically (see D21). It only ever decodes camera frames, never fetches or evaluates remote data. | Low | Accepted |
| 31 | Label OCR was tested only on labels rendered by the browser (clean Arial text), not on photos of real packaging. Curved wrappers, glare, foil and small print will read worse; the form is always editable and warnings show, but expect to correct numbers. | Medium | Unverified on real photos |
| 32 | OCR reads "g" before ")" as 9 ("50g" -> "509g"); only flagged, not repaired (see D23). The English model only: labels in other languages or "Energy kJ" only layouts may not parse. | Low | Accepted |
| 33 | OCR memory/speed on real phones is untested: a worker plus a ~4 MB wasm core and an image decode at reduced size should fit, but low-memory phones (iOS Safari) may struggle; the ZXing fallback decodes up to 960 px frames on the main thread every 250 ms and may feel janky. HEIC photos are not handled specially. | Medium | Unverified on a device |
| 34 | UPC-E codes are not expanded to UPC-A (see D20). A second photo while one is still being read starts a second worker (the first result is ignored, not cancelled). | Low | Open |
| 35 | `@zxing/library`'s package.json says MIT but its LICENSE file is Apache-2.0; `tesseract.js` ships no licence file (package.json says Apache-2.0), so the Apache text from `tesseract.js-core` is included. Hashes of vendored files were not compared with upstream. | Low | Documented |
| 36 | Label camera/upload buttons (D24) are unverified on real devices. Possible issues: on Android a camera app launch can reload an installed PWA and drop the half-filled form; the two buttons overlap on iPhone. The tests for this change are source-text checks only (the project has no DOM test library); the disabled-state, 25 MB refusal and input-clearing behaviours are covered by the manual checklist in `docs/specs/label-camera-or-upload.md`. | Low | Unverified on a device |
