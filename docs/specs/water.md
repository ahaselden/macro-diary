# Spec: water, a Diary card of cups (backlog item 23, schema 12 to 13)

## Purpose
The Diary gets a "Water" card: a row of cup pictures (one cup = 8 fl oz, about 240 ml) the user taps to fill, per day, towards a goal that is editable in Settings (default 8 cups = 64 oz). The day's water is saved data (`state.water`, schema 13) that travels with sync and backup, one record per day like `state.activity`.

Written before the implementation by the test designer. The owner request of 2026-11-14 is taken as given. Where the request left a name, rule or string open, this spec FIXES it (marked "decided here") so the tests can pin it; the owner can change any of these in review before the build, and the implementer must then ask for the test to be changed, not edit it. Tests: `tests/water.test.js` (W1-W22). Water is NOT added to calories or macros, the report JSON and CSV are unchanged (W12), and there is no ring dial, bottle, or reminder in this feature.

### Saved shape (decided here)
- `state.water = { 'YYYY-MM-DD': { updatedAt, halves } }`. `halves` is the day's total in HALF-CUP units, an integer 0..80 (80 = 40 cups). A record with `halves: 0` is KEPT (an explicit undo must win a sync); a day with no record means no water. No tombstones (like activity).
- `state.goals.waterCups`: a whole number 1..40, default 8. Anything unusable (not a number, not an integer, below 1, above 40, NaN, Infinity, null, boolean) becomes 8, never clamped. Numeric text such as `'12'` is not pinned (open question 3).
- `state.waterTap`: `'half'` or `'whole'`; anything else becomes `'half'`. Top-level, travels with the settings record.
- Day record from untrusted input (`sanitizeWaterDay`): a plain object whose `halves` is a number and an integer in 0..80, else `null` (the record is dropped, never clamped). `updatedAt` a finite non-negative number, a missing or bad one becomes 0 (the record is kept). Result is a NEW object with exactly the two keys.
- Migration 12 to 13 adds `water: {}`, `goals.waterCups: 8`, `waterTap: 'half'`; every other value is kept; a version-13 save keeps its water, goal and tap choice.
- Old tests that pin the number 12 are listed under "Superseded tests".

### `js/domain/water.js` (decided here)
- **Units.** `weightUnit === 'g'` gives millilitres (1 cup = 240 ml, 1 half = 120 ml); `weightUnit === 'oz'` gives fluid ounces written `oz` (1 cup = 8 oz, 1 half = 4 oz). Amounts are plain integers without thousands separators (`1920 ml`). Other weightUnit values: open question 4.
- `waterModel(state, day)` returns `{ halves, goalCups, unit, cups, text, goalText, over }`:
  - `halves`: the day's record's halves if `day` is a real date (`isDateKey`; so `__proto__` and friends are never read) and the record is an own property of `state.water` that `sanitizeWaterDay` accepts, else 0. `goalCups`: `sanitizeWaterCups(state.goals.waterCups)`. `unit`: `'ml'` or `'oz'`.
  - `cups`: an array of length `max(goalCups, ceil(halves / 2))`. Cup i (1-based) is `'full'` when `halves >= 2i`, `'half'` when `halves === 2i - 1`, else `'empty'`. Each item is `{ state, over, label }`; `over` is true when `i > goalCups` (only cups that are shown beyond the goal, which are always filled at least half). `label` is `Cup i of N, <empty|half full|full>` where N = `cups.length`, plus `, over goal` when over. Example: `Cup 3 of 8, half full`, `Cup 9 of 9, full, over goal`.
  - `text`: `<cups> of <goal> <cup|cups>, <amount>`; `<cups>` is `halves / 2` written with no decimal for a whole number and `.5` for a half (`3`, `2.5`); `<goal>` is `goalCups`; the noun is `cup` only when goalCups is 1, else `cups`; amount as in Units. When `over` the text ends `, over goal`. Examples (goal 8): halves 6 metric `3 of 8 cups, 720 ml`; imperial `3 of 8 cups, 24 oz`; halves 5 `2.5 of 8 cups, 600 ml` / `20 oz`; halves 0 `0 of 8 cups, 0 ml`; halves 18 imperial `9 of 8 cups, 72 oz, over goal`.
  - `over` (model): `halves > 2 * goalCups` (exactly at the goal is not over).
  - `goalText`: `<goalCups> <cup|cups>, <amount of goal>`: `8 cups, 64 oz`, `8 cups, 1920 ml`, `1 cup, 8 oz`, `12 cups, 2880 ml`.
  - Pure; never mutates `state`; never throws on a missing state, goals, water, junk day; no `NaN`, `undefined`, `null`, `[object` in any string.
- `nextHalves(current, cup, mode)` (the tap rule, decided here). `cup` is the 1-based number of the tapped cup (the same N as `data-cup`). `current` is the day's halves; anything that is not an integer 0..80 counts as 0. `mode` is `'half'` or `'whole'`; anything else is `'half'`. Let `before = 2 * (cup - 1)` and `own = clamp(current - before, 0, 2)` (0 empty, 1 half, 2 full: the tapped cup's own state). The tapped cup's next state is: in `'half'` mode empty to half, half to full, full to empty; in `'whole'` mode empty to full, half to full, full to empty. The result is `before + next`. So tapping cup N fills every cup before it, and tapping a full cup N empties N and every cup after it (the total drops to the cups before N). `cup` must be an integer 1..40 (a number, not text); otherwise the result is the sanitised `current` unchanged. The result is always an integer 0..80.
- `setWater(state, day, halves, now)` (`entries.js`, mutates `state` like its neighbours): sets `state.water[day] = { updatedAt: now, halves }` (creating `state.water` when missing) and returns that record. Returns `null` and changes nothing when `day` is not a real calendar date `YYYY-MM-DD` (`isDateKey`), when `halves` is not an integer number 0..80 (never clamped), or when `now` is not a finite number >= 0. It does not touch `settingsUpdatedAt`, `days` or `tombstones`.
- The goal and the tap mode are settings: they change through `touchSettings(state, now)` like the other goals.

### `js/ui/water.js`: markup that `waterHtml(model)` returns (the inner HTML of `#water`; decided here)
- The visible title `Water`; a text line `<element id="waterText">` containing `model.text`; `<element id="waterGoal">` reading `Goal: ` + `model.goalText`.
- A container `<div class="water-cups" id="waterCups" role="group" aria-label="Water cups">` with one real `<button type="button" class="cup cup-<state>[ over]" data-cup="N" aria-label="<model label>">` per cup, `N` counted from 1 in order (taken from the position, never from model data), at most 40 buttons. Each button holds one inline `<svg ... aria-hidden="true">` (a simple tumbler outline). A `half` or `full` cup's svg contains one `<rect class="cup-fill" fill="var(--water)" ...>` whose height is half (`half`) or all (`full`) of the cup's inside; an `empty` cup has no `.cup-fill`. Over cups additionally carry the class `over` AND say `over goal` in their aria-label and, when the model is over, in `#waterText`; colour alone never carries the meaning.
- Every dynamic string goes through `esc()`. Unknown or missing pieces render as an empty cup / empty text, never `NaN`/`undefined`/`null`.
- After a tap the card re-renders and keyboard focus returns to the cup with the same number, or to the last cup if that cup no longer exists (tapping a full over-goal cup removes it).

### Wiring and settings (decided here)
- `index.html`: `<div class="card" id="water"></div>` in `#v-diary` AFTER `#activityLine` and BEFORE `#meals` (order `#dials`, `#activityLine`, `#water`, `#meals`). It is a plain card, not a button.
- Settings goals card: `<input id="gWater" type="number" inputmode="numeric" min="1" max="40" step="1">` with `<label for="gWater">Water (cups)</label>`; a `<select id="waterTap">` with `<label for="waterTap">Tapping a cup</label>` and exactly two options `half` ("Half cups") and `whole` ("Whole cups"). Changing either calls `touchSettings(state, Date.now())` and `save()` and re-renders the water card.
- Theme: `--water` is defined in `:root` and in EVERY `[data-theme=...]` palette block, a blue.

### Sync and backup (decided here)
- Record key `water:YYYY-MM-DD`, value `{ water: { updatedAt, halves } }`, record `updatedAt` = the day's `updatedAt`. Emitted for every valid day record, including `halves: 0`; a state without `water` emits none and does not throw. `isSyncKey` accepts `water:YYYY-MM-DD` (shape only, like activity); the real-date check happens when the record is applied, so `water:2026-13-01` is ignored there.
- `merge.js`: per day the newer `updatedAt` wins as a whole; an equal stamp gives the same winner whichever side is local (the larger canonical JSON, as for activity); with `preferLocal` a tie goes to the local record (restores). Only keys that are real dates become buckets (`__proto__`, `constructor`, `2026-13-01` never do). Tombstones do not apply. The merged state always has a `water` object.
- The settings record carries `goals.waterCups` (inside `goals`) and `waterTap` (next to `weightUnit`). Settings stay one record, newest `settingsUpdatedAt` wins as a whole.
- **Old-device rule (decided here, the same as `dials` in `dials-simplify.md`):** a settings record or backup that has NO `waterTap`, or whose `goals` has NO `waterCups` (made by a build before this feature) never resets this device's value, even when it wins the rest of the settings. A present but unusable `waterTap` also leaves this device's value alone. This is a deliberate exception to the existing goals handling, which resets a missing `steps` or `sleepH` to the default (D56, still true for those two): the implementer needs to look at whether the raw record had `waterCups` (the sanitised goals always have it) and keep the local number otherwise. See open question 1.
- Backup export is `JSON.stringify(state)`, so water, the goal and the tap choice travel in it. Restore merges with the sync rules.

## Edge cases and hostile input (covered by the tests above)
Empty state and missing keys; huge or negative numbers; `NaN`, `Infinity`; numbers as text; booleans; arrays and objects where a number belongs; `__proto__`, `constructor` as a day or key; `JSON.parse` objects with an own `__proto__` key; HTML in model strings; frozen inputs; a cup count far above 40; a half cup beyond the goal; two devices with equal stamps; synced or imported records written by an older build.

## Open questions (for the owner; tests avoid depending on them unless said)
1. **Goal handling for an old device (decided here, please confirm).** Existing goal fields (steps, sleepH) reset to the default when an old-device settings record wins (D56). For `waterCups` this spec chooses the better rule: a record or backup without it keeps this device's number (W16, W17 pin it). The simpler alternative, "treat `waterCups` like steps and reset to 8", is acceptable to the owner per the request; if chosen, W16 and W17 must be changed by the test designer, not the implementer.
2. **Rounding a goal such as 7.5.** Decided here: not rounded, unusable, becomes 8 (the steps goal rounds; this one does not, as the request said "whole number ... unusable value gives the default, never clamped").
3. **Numeric text as a goal (`'12'`) and as `halves` (`'4'`).** Not pinned for `waterCups` and `sanitizeWaterCups`. For `halves` text is rejected (W3).
4. **`weightUnit` other than `'g'` and `'oz'`** (never produced by `sanitize`): the request says "otherwise fl oz"; only `'g'` and `'oz'` are tested.
5. **Settings input that is unusable** (`0`, `99`, `abc`, empty): the saved goal becomes the default 8 (the UI may instead keep the previous value; only "not 0 or 99 or NaN" is pinned in C9).
6. **Unit word.** `oz` (as in the request's examples), not `fl oz`.
7. **Half cup beyond a goal of 40** is not possible (cap 80 halves).
8. **Pluralising `0.5 of 1 cup`.** The noun follows the goal (`1 cup`), so `0.5 of 1 cup, 4 oz`.
9. **Focus after tapping a cup that disappears** (over-goal cup emptied): the last remaining cup (C5).
10. **Edit of past days older than the diary's range**: no limit beyond what the day navigation allows.
