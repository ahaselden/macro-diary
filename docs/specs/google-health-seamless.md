# Spec: Google Health seamless sync (follow-up to google-health-sync, `docs/specs/google-health-sync.md`)

## Purpose
Make Google Health sync need no setup and (where Google allows it) no tap: the app ships a default Client ID (a public value, not a secret), remembers when it last synced on this device, and when the app opens (or becomes visible again) after 3 hours or more it tries ONE quiet sign-in, falling back to the existing one-tap button. No backend, no background sync (a web page cannot do that), no refresh token, no saved-shape change.

Written before the implementation by the test designer. Where the request left a rule open this spec FIXES it ("decided here") so tests can pin it; the owner can change it before the build, and the implementer must then ask for the test to be changed, not edit it. Tests: `tests/google-health-seamless.test.js` (N1-N19 behaviour with fakes, N20-N22 WEAK source-text checks). The existing `tests/google-health-sync.test.js` must keep passing unchanged. Owner decisions already made (not re-opened here): default Client ID shipped in the app; attempt on open when stale, quiet first, one-tap fallback; the Google project is switched to In production by the owner in the Google console (not by code), at most about 100 users.

## Contract

### `js/domain/google-health-api.js` (pure; `now` is always an argument, no `Date.now`)
- `shouldAutoSync({ enabled, hasClientId, lastSyncAt, now, minHours = 3 }) -> boolean`.
- `syncAgoText(lastSyncAt, now) -> string`.
- Existing exports (`checkClientId`, `applyHealthSync`, `healthSyncText`, ...) unchanged.

### `js/services/google-health-api.js`
- `DEFAULT_CLIENT_ID` (string, public by design; `''` or passes `checkClientId`; value never asserted by tests).
- `createClientIdStore(storage, defaultId = '')` -> `{ get(), usingDefault(), set(text), clear() }`.
- `SYNC_PREFS_KEY = 'macrodiary.googlesync.v1'`, `createSyncPrefs(storage)` -> `{ getLastSyncAt(), setLastSyncAt(ms), getAuto(), setAuto(bool) }`.
- `createHealthSync({ fetch, loadGoogle, now }).run(clientId, { silent = false } = {})`.
- Existing exports (`CLIENT_ID_KEY`, `GIS_URL`, `SCOPE`, `preloadGoogle`, ...) unchanged.

### `js/ui/health-sync-view.js`, `index.html`
`initHealthSync()` stays the only export (called once by `main.js`, which must not itself decide anything about auto sync). New ids inside `#ghSyncCard`: `#ghSyncAuto` (checkbox) and `#ghSyncLast` (small text). The index.html markup of `#ghSyncDiary` stays `hidden`; the view shows it.

### Decided here

**Client ID store.** `get()`: the device's saved ID if it passes `checkClientId`, else the default if it passes `checkClientId` (returned trimmed), else `''`. `usingDefault()` is true exactly when `get()` returns the default (so false when nothing is available and when a saved ID wins). A default that fails the check is treated as no default (`''`), never thrown. `set(text)` and `clear()` as before: `clear()` removes only the device's own ID. The default is never written to storage. A secret (`GOCSPX-`) is refused by `set` and never stored. One-argument use is identical to today.

**`shouldAutoSync`.** True only if `enabled` is true, `hasClientId` is true, `lastSyncAt` is a finite number > 0, `now` is a finite number, and `now - lastSyncAt >= minHours * 3600000`. `lastSyncAt` equal to `now` or in the future is false (a stamp in the future means the clock moved back). `minHours` that is not a finite number > 0 means 3. Strings are never parsed (`'1000'` is junk). Never throws, even for a missing/`null` argument or a throwing getter: returns false. A missing or 0 `lastSyncAt` is false: the first sync on a device is always an explicit tap with consent, never an automatic popup.

**`syncAgoText(lastSyncAt, now)`.** `''` when `lastSyncAt` is not a finite number > 0, `now` is not a finite number > 0, or `lastSyncAt > now`. Else `d = now - lastSyncAt` and the text is `Last synced ` + : `just now` for `d < 1 minute`; `a minute ago` / `N minutes ago` for `d < 1 hour` (floored, N = 2..59); `an hour ago` / `N hours ago` for `d < 24 hours` (floored); `a day ago` / `N days ago` (floored, no upper unit, so 40 days is `40 days ago`). Plain text only.

**`createSyncPrefs`.** One localStorage key `macrodiary.googlesync.v1`, outside the saved diary data (so it is in no backup, export or sync record: same reasoning as the Client ID key). The value is one JSON object with at most the keys `lastSyncAt` and `auto` (decided here so garbage can be tested). `getLastSyncAt()`: a finite number > 0, else `0`. `getAuto()`: `false` only when the stored `auto` is the boolean `false`; `true` for nothing stored, garbage, or any other value. Stored values are validated on read from OWN properties only (a `__proto__` key in the JSON is not data). `setLastSyncAt(ms)` stores only a finite number > 0; `setAuto(b)` only a boolean; anything else is ignored (the previous value stays). Setting one field never changes the other. Never throws on a missing, throwing or garbage storage. No token, ID or email is ever in it.

**`run(clientId, { silent })`.** `silent` true: `google.accounts.oauth2.initTokenClient` gets the same config as today and `requestAccessToken({ prompt: 'none' })` is called (Google must not show a sign-in or consent screen). Not silent (omitted, `undefined`, `{}`, `{ silent: false }`): byte-for-byte today's behaviour, and `prompt: 'none'` is never sent (a tap must be able to show the sign-in). Silent mode, every failure BEFORE a token exists (response `error` such as `interaction_required`, `login_required`, `consent_required`, `access_denied`, `popup_failed_to_open`, `popup_closed`, other codes, init or request throwing, script not loadable, no usable token) resolves `{ ok: false, silent: true, message }`, where `message` is exactly the text a normal run gives for the same failure (so the UI can ignore it). Failures AFTER a token was obtained (HTTP 401/403/429/other, not linked, network, unreadable) resolve exactly as today, with NO `silent` key, so the UI shows them. A silent success is `{ ok: true, days }` with the same two Health requests as a normal run. The one-at-a-time rule is shared by both modes and released after every outcome. Invalid or empty Client ID: refused as today (not a sign-in failure, no `silent` flag required).

**UI.** Settings card (`#ghSyncCard`):
- A line telling which ID is used: `Using the built-in Client ID.` (default in use), `Using the Client ID saved on this device.` (saved ID in use), nothing when no ID is available. Written with `textContent`.
- Checkbox `#ghSyncAuto`, label text exactly `Sync when I open the app (if the last sync is over 3 hours old)`, checked state = `getAuto()` (default checked), changing it calls `setAuto`.
- `#ghSyncLast` shows `syncAgoText(getLastSyncAt(), Date.now())` (empty when unknown), refreshed after every sync and when Settings opens. Textual only.
- `Save` -> status `Client ID saved on this device.`; `Remove` -> status `Client ID removed. Using the built-in Client ID.` when a default exists, else `Client ID removed.` (decided here). The input box shows only the device's own saved ID (empty when the default is in use; it is never filled with the default).
- `#ghSyncDiary` is visible whenever `get()` is non-empty (default or saved), hidden otherwise. A small text near it is optional and untested.
- Every successful sync, including a no-change one (nothing added or updated), calls `setLastSyncAt(Date.now())`. A failed sync never does.

**Automatic attempt.** On app start (`initHealthSync`) and on `visibilitychange` when `document.visibilityState === 'visible'`: if `shouldAutoSync({ enabled: getAuto(), hasClientId: !!store.get(), lastSyncAt: getLastSyncAt(), now: Date.now() })`, the view runs ONE `sync.run(id, { silent: true })`. Further rules: never while another sync (manual or automatic) is running; never two at once; at most one silent ATTEMPT per page load per 3 hours of in-page time, success or failure, so a failing quiet sign-in is not retried on every tab switch (the attempt time is kept in memory, not in storage; decided here, see open question 3); never when auto is off; never before a first successful sync on this device; never with no ID. A silent result with `silent: true` (sign-in could not be done quietly) shows NOTHING: no toast, no status text, no change to the buttons. A silent success applies the days exactly like a manual sync (`applyHealthSync`, `save`, `emit('diary:changed')`), sets `lastSyncAt`, shows the usual status text in `#ghSyncStatus` and may toast it. A silent run that failed after the token (no `silent` flag) shows its normal message in `#ghSyncStatus` (a toast is optional).

### What unit tests can and cannot prove
Pure functions, the store, the prefs and `run({ silent })` with fakes (N1-N19) are real tests that can fail. N20-N22 are source-text checks (same pattern as T1-T5 of `google-health-sync.test.js` and test 21 of `search-serving-calories.test.js`): they prove ids, strings and calls are present, NOT that the wiring behaves. The rules in "Automatic attempt" (once only, not concurrent, not before the first sync, silent failure shows nothing) exist only in the view and are proven only by the headless checklist.

## Edge cases and hostile input
- Default Client ID: empty, whitespace, secret, wrong type, a default that contains HTML or a secret next to a valid ID (all ignored).
- Stored Client ID garbage with a good default (default used); throwing/missing storage.
- Prefs: not JSON, JSON of the wrong type, strings/arrays/objects as values, `1e999` (Infinity), `__proto__`/`constructor` keys, HTML in a value (never rendered: `textContent`).
- `shouldAutoSync` / `syncAgoText`: NaN, Infinity, strings, negative, 0, missing, huge (year 2286 style numbers), future stamps, getters that throw.
- Clock moved back: stamp in the future means no auto sync and an empty "last synced" line until the clock catches up (the stamp is not rewritten by reading).
- `run`: silent with the script blocked/offline; Google answers a quiet request with `popup_failed_to_open` (browser blocked a popup it needed for an interactive step); a token callback arriving after an error callback (unchanged guard).

## Security and privacy
- The default Client ID is public by design but still validated by `checkClientId`; a default that looks like a secret is ignored and never used.
- No token is ever stored, logged, put in a URL or shown; the new prefs hold `lastSyncAt` and `auto` only; the Client ID and prefs keys are outside `macrodiary.v1` so they are in no backup, export or sync record (S2 of the existing tests already covers the ID; N12 covers the prefs).
- Stored prefs and Google messages are written with `textContent` only.
- `silent` never hides a failure after the token (an expired scope or a 403 should be visible); it only hides "could not sign in quietly".
- Quiet sign-in uses `prompt: 'none'`: Google shows no screen, so the app never pops a window by itself. The first sync on a device is always an explicit tap.

## What cannot be tested automatically
- Whether Google really allows `prompt: 'none'` for this origin / browser / installed app, third-party-cookie and tracking-prevention behaviour, the real consent and "not verified" screens, the real token lifetime, real data. Unit tests use fakes; the headless run stubs Google completely (it can prove what the app does with each stubbed answer, not what Google does).
- The look of the new lines and checkbox on a phone.
- N20-N22 are weak (text only); the checklist below is the real UI test.

Put the app in the background over 3 hours and bring it back: the same quiet attempt (visibility). Covered by headless? no: real phone lifecycle (C11, C17 cover the rule with stubs).
- **R6 Second device with no pasting.** On another device open the site: no Client ID is needed (`Using the built-in Client ID.`); the first sync needs one tap and consent. Covered by headless? no: second real device.
- **R7 Clock moved back.** Set the phone clock a day back after a sync: no automatic attempt and an empty `Last synced` line until the clock is right again. Covered by headless? no: system clock (C21 covers the stamp in the future).

## Open questions
1. **Where `prompt: 'none'` goes.** Specified as `requestAccessToken({ prompt: 'none' })` (the Google Identity Services place for it). A request-level `prompt` is the documented route for token clients; if the owner's test of R2 shows Google ignores it, the approach changes, not just the test.
2. **`DEFAULT_CLIENT_ID` value.** Tests accept `''` or a valid ID. The headless checklist needs a build with a known default [D] and one without [N]; the shipped value is the owner's/implementer's choice. Note the existing headless items C1/C2/C10/C19 of `google-health-sync.md` assume no built-in ID (see C24).
3. **Retry policy after a quiet failure.** Decided here: one silent attempt per page load per 3 hours of in-page time, success or failure. The request said "at most once per 3 hours of staleness"; a failed attempt leaves the stamp unchanged (still stale), so without an in-memory attempt time every tab switch would re-try. Alternative: persist the attempt time (a third pref field), which would change N12 ("only two fields").
4. **Busy result in silent mode.** A silent run while another is running: tests only require `{ ok: false, busy: true }` (whether it also carries `silent: true` is open; the UI should not call it).
5. **Invalid/empty Client ID in silent mode.** Refused as today; tests do not pin whether `silent: true` is added.
6. **Truthy non-boolean `enabled` / `hasClientId`** (`1`, `'yes'`) are deliberately not tested (the UI passes booleans); falsy values are false.
7. **`minHours` of 0** is treated as bad (-> 3) by this spec; not pinned by the tests (negative, NaN, strings, Infinity are).
8. **Optional small text near `#ghSyncDiary`** (last-sync line): untested; if added it must also use `textContent`.
9. **Persisted prefs format.** Decided here as one JSON object with keys `lastSyncAt` and `auto`; N11/N12 pin that shape.
10. **The empty `lastSyncAt` the user sees on a device that was synced before this feature shipped:** there is no stamp, so the first automatic quiet attempt happens only after one more manual sync. Intended ("first sync always needs a tap"), flagged so the owner can say if an existing synced device should instead be backfilled (it cannot be known).
11. **Quiet sign-in vs. the 1-hour token.** Each quiet success gets a fresh 1-hour token and nothing is stored; the app cannot refresh in the background. Intended.
